## Approach

- Settle the alert emphasis from Yeti, not from the reviewers' guesses: with `vendor/yeti/src/components/alert/alert.css` loaded, measure in Chromium, in both schemes and for the default variant, Yeti's ring (`--yeti-color-focus`) against the fill of a default-emphasis, a high-emphasis, and a low-emphasis alert, and record the ratios in the Log. The reset in `packages/ngx-yeti/ngx-yeti-globals.css` keeps only the emphasis values whose fill the ring reads on at least 3:1 (expected from the CSS: the default emphasis only; low paints no fill and high's default-variant fill is the ring's colour). An alert the reset leaves out takes the band ink like any other content of the band.
- Keep T058's and T060's design: only the alert entry narrows and the three subsumed entries go; the reset stays one zero-specificity `:where()` rule before the 20 paint lines; no `--_yeti-*` token is read (the stylesheet spec's `privateReads: []` forbids it, so `--_yeti-on-variant` is not an option); no `@scope`; no forced-colours change. The comment says what the code cannot (why an alert of one emphasis resets and the others do not), with no measurement, date, or task id.
- Drop `.dropdown > [popover]`, `.nav > ul[popover]`, and `.dialog` from the reset, from `yetiSurfaces` in `packages/ngx-yeti/src/accessibility.node.spec.ts`, from the `'A11Y-35'` string of `sanctionedSelectors` in `packages/ngx-yeti/src/published-output.node.spec.ts`, and from every prose copy; `[popover]` and `dialog` already match them. Building the sanctioned string from a shared array is optional.
- `accessibility.node.spec.ts`: the surface test's title says it checks the pinned surfaces, not every surface; `inkResets` returns an empty list (or throws) when the sheet has no reset, and its self-test is named for what it checks. Pitfall: `yetiSourceSelectors` drops attribute values, so a narrowed alert entry such as `.alert:not([data-emphasis='low'], [data-emphasis='high'])` will not match Yeti's source as written; the source check must still fail when a pin move renames `.alert` or its `data-emphasis` values (check the class and each attribute value the entry names).
- `box--paint` (`packages/ngx-yeti/box/src/box.stories.ts`), in both schemes, inside `primary` bands padded by at least 4px as the existing ring bands are: a link or close button in a low-emphasis alert, ring asserted at least 3:1 against the band; a link or close button in a high-emphasis alert of the default variant, ring asserted at least 3:1 against the alert's computed fill. Pitfall: Storybook loads an item's CSS only through its directive and alert is not an M002 item, so the story loads Yeti's alert stylesheet itself (for example a story-local host that calls `injectYetiItemStyles('alert')` from the public `ngx-yeti/styles` entry) and waits until it applies before measuring; the alert markup is Yeti's own (`class="alert"`, `data-emphasis`), since there is no alert directive. Keep every existing assertion and band order check.
- Show the new cases can fail and record each run in the Log: with the reset's alert entry restored to the whole `.alert`, the low-emphasis case and the high-emphasis case each fail at their named assertion; restore afterwards.
- Upstream row: measure Yeti alone (no package stylesheet) for a control focused by keyboard in a high-emphasis alert outside any band, for each alert variant in both schemes, and add one row to `docs/specs/upstream-bugs.md` (next free id after Y17) with the ratios that are under 3:1 and the alert.css lines. The package does not fix that outside-band case in this task, so no new ledger row; A11Y-35 covers only rings inside a painted band.
- Records, each made true for the narrowed list: ledger row A11Y-35 (package column selector text, Verified with the new measurements, Tested-by with the new story cases); the CHANGELOG sentence at `packages/ngx-yeti/CHANGELOG.md:37` (an alert of the default emphasis, not every alert; no dropdown or nav panel entries); the `box.md:207` Departures row in `.claude/skills/ngx-yeti-specs/SKILL.md`; line 48 of `.claude/skills/ngx-yeti-accessibility/SKILL.md` if it names the surfaces; step 5 of `.claude/skills/yeti-pin/SKILL.md` (the count of Yeti surface selectors, now not 10, and that a pin move that adds a repainting surface or an emphasis value needs the list re-derived). `docs/specs/` is otherwise immutable; only `ledger.md` and `upstream-bugs.md` change.
