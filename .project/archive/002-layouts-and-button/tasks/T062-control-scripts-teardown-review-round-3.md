## Approach

- Storybook dead-PID path (item 8): before removing the state file, look for surviving members of the recorded tree and for a listener on the recorded port, as the live path does; a survivor or a busy port ends `down` with exit 1 and "teardown incomplete", naming the survivors and the port, with `portFree` measured. On this path the state file is still removed, as g3-silent-failure F1's minimum says ("report `portFree` from a real `portAnswers` and exit 1 when the port is busy, even if the state file is removed"): the root is dead, so a kept file could only make every later `down` fail the same way, which is the lockout Lars deferred. Survivors on both paths count only when PID and start time both match the snapshot, as yeti-app's `down` does. The dead-PID test asserts the port is free after `down`, and does not free it itself beforehand in a way that hides the check (for example: kill only the recorded root so a child can outlive it, or assert after `down` that the port is free and the outcome names what `down` found).
- Malformed session file (item 9): in both scripts an entry that cannot be read or parsed counts as possibly open; `down` still kills the tree, prints its JSON result, and reports the entry (the file path) as incomplete teardown. Prove it with a test that does not write into the real playwright-cli registry of this machine: pass the registry folder to the function or the script (an export or an environment variable read only by tests), point it at a temporary folder holding an empty `.session` file, and assert the result.
- Outcome (item 10): one JSDoc union of session outcomes, `left-open` among them, in each script, and one function that says whether an outcome is a failed teardown; both `down`s and Storybook's `endTeardown` call it; the optional `listedOpen` field and the compound predicates go. Each SKILL.md's outcome table names `left-open`.
- Types (item 11): the Storybook preview global is declared once in `.claude/skills/control-ngx-yeti-storybook/scripts/storybook-preview.d.ts` and reaches the script through a reference that `tsc -p tsconfig.scripts.json` follows (add it to `tsconfig.scripts.json` only if needed); no `/** @type {unknown} */` cast is left in the Storybook script. yeti-app's `queryListeners` reports a failed spawn without throwing and passes a `timeout` to `spawnSync`, treating a timed-out query as a failed one. Storybook's teardown result has one typed shape on both paths, with `portFree` measured, not written as a literal.
- Keep every other outcome and exit code the SKILL.md tables already state; T047's and T055's refusal, flag, and daemon cycles stay. Keep both scripts typed (Interface contract).
- The suites build and launch on fixed ports (4000, 4200, 4310 to 4312, 4400, 4401); the orchestrator runs this task with no other heavy command, coder, or NVDA run. Never set `NX_DAEMON`.
