# T040 — Withhold a named once arrival with one package rule, and fail when Yeti fixes its once bug

## Context

Build repair before wave 4. User rulings, verbatim (2026-10-11): "If/when you have high confidence in fixing yeti-css' `once` bug in ngx-yeti, fix it in ngx-yeti in a way that we are notified if/when yeti-css fixes it so that we can remove our fix from our package." and "Regarding the once bug, of course it also needs an entry in one or both of our ledgers". A spike on 2026-10-11 (a sidecar at 7e0045f; Playwright 1.63.0's Chromium 153, Firefox 155, and WebKit 26.6, with identical results in all three) reached high confidence for one rule in the package's accessibility stylesheet, guarded by a test that fails when Yeti fixes the bug. This task lands both, with ledger row A11Y-33 (the id is unused; check again before writing it), a corrected upstream row Y14, and the Departures row.

The bug (upstream Y14), measured on a static page with Yeti's built CSS and through `yetiEnter`:

- Yeti withholds a `once` arrival with `.enter[data-once] { animation: none }` at specificity (0,2,0), and with `.enter[data-once][data-stagger] > *` at (0,3,0). Its named arrivals set `animation-name` at (0,3,0) or more, and the staggered `slide` with `data-side="end"` or under `:dir(rtl)` at (0,4,0).
- So on eight forms the named rule wins the name while `animation: none` wins every other longhand: the element runs a 0 s animation at load, with one `animationstart` and no moving frame. When `data-once` is removed the duration becomes 0.6 s but the name does not change, so no animation starts. The element never visibly arrives, on load or on scroll. Row Y14 says it "plays its rise on load" and that staggered hosts are withheld correctly; the first is wrong, and the second is wrong for two forms.
- The eight forms: `rise`, `fall`, `scale`, `slide`, `slide` with `side="end"`, `slide` in a right-to-left page, a staggered `slide` with `side="end"`, and a staggered `slide` in a right-to-left page. The default fade, and a staggered fade, `rise`, `fall`, `scale`, or left-to-right start-side `slide`, are withheld and arrive correctly (staggered `fall` and `scale` inferred from `rise`).
- Content stays visible throughout, with JavaScript on or off.
- Through the real directive, 24 of 30 cases fail without a fix: the 8 forms in 3 engines.

The fix, measured. Every consumer's global stylesheet declares `@layer yeti, ngx-yeti;`, so a normal declaration in `@layer ngx-yeti` beats any Yeti declaration whatever its specificity. One rule there, on `.enter[data-once]:not([data-stagger])` and `.enter[data-once][data-stagger] > *`, with the one declaration `animation-name: none`, gave: 30 of 30 through the directive; all 14 forms of the static page withheld (name `none`, no `animationstart`) and then arriving with exactly one `animationstart` at 0.6 s; 36 of 36 on the Fixture app across the development and production builds (JavaScript off, before hydration, hydration, arrival, no replay, reduced motion); and the existing enter and accessibility specs unchanged and green. The other candidate, holding `data-enter` back in the directive while the host is withheld, also works, but it changes the server HTML and breaks three existing tests that state enter.md's attribute contract; it is not chosen.

Placement is not yet confirmed by the user. The spike recommends `packages/ngx-yeti/accessibility.css`; the user has not said whether a rule that closes no accessibility criterion may live there or needs a stylesheet of its own. Build it there and keep it easy to move. A consumer whose global stylesheet leaves the accessibility stylesheet out keeps today's behaviour.

## Approach

- The rule: exactly the two selectors and the one declaration of Context, as one self-contained block inside the existing `@layer ngx-yeti` block: its own comment, no selector list shared with another rule, and nothing that depends on its position. Moving it to another stylesheet is then a cut and paste plus its table entry and its docs.
- The rule's comment states the mechanism (Yeti's `animation: none` loses the name to its own named arrivals; this layer outranks every Yeti layer), names upstream Y14 and ledger row A11Y-33, and says the rule goes when the Y14 test of the enter spec fails. No date, run count, or task id. The file's header comment says there is one other rule, the Firefox scale workaround; it now names two.
- The rule stays inside the limits `packages/ngx-yeti/src/accessibility.node.spec.ts` enforces (inside the layer, no `--_yeti-*` token, no package class); that spec needs no change. Add the two selectors to `sanctionedSelectors` under A11Y-33 in the same commit (Interface contract).
- No directive code changes. The host bindings and the logic of `packages/ngx-yeti/enter/src/enter.ts` stay as they are, so the server HTML, the hydration contract, and every existing expectation of the enter specs stay as they are. Only the doc comment of the `once` input gains one sentence: a named arrival is withheld through the package's accessibility stylesheet (ledger row A11Y-33).
- Layer 2, fix test, in `packages/ngx-yeti/enter/src/enter.spec.ts`: ten forms through the real directive, each created below the fold with `once`, with the global stylesheet (`packages/ngx-yeti/.storybook/styles.css`, which ends by importing the accessibility stylesheet) and Yeti's built enter file loaded the way `packages/ngx-yeti/lift/src/lift.spec.ts` loads Yeti's CSS. While withheld: `data-once` present, the computed `animation-name` is `none`, opacity 1, no `animationstart`. ## Interface contract

- Playwright helpers (T036): the entry `@ngx-yeti/testing/playwright` (`packages/ngx-yeti-testing/src/playwright.ts`, mapped in tsconfig.base.json) is for the two e2e apps and exports `interface Box { readonly top: number; readonly right: number; readonly bottom: number; readonly left: number; readonly width: number; readonly height: number }`; `rect(locator: Locator): Promise<Box>`; `childRects(parent: Locator): Promise<Box[]>`, the boxes of the element's children in DOM order; `usedLength(scope: Locator, length: string, axis?: 'inline' | 'block'): Promise<number>`, the used px size of a CSS length such as `var(--yeti-width-md)`, read from a probe appended to `scope`, on the inline axis unless `axis` says otherwise; `horizontalOverflow(page: Page): Promise<number>`, how far the document is wider than the viewport; `resize(element: Locator, width: number): Promise<void>`, which sets the element's inline size in px and throws when it is not an HTMLElement; and `expectItemSheetsApplied(page: Page, items: readonly string[]): Promise<void>`, which expects one item link per named item in the head and waits until each has a stylesheet with at least one rule. No e2e spec declares a copy of these, and no other helper checks that an item sheet has loaded.
- Fixture route helpers (T036), in `apps/yeti-app-e2e/src/support`: `standard-cases.ts` exports `describeStandardRouteCases(cases: { readonly item: string; readonly prefix: string; readonly route?: string; readonly liveHost: string; readonly leaveLink: string; readonly styled: { readonly property: string; readonly value: string | RegExp } }): void`, called once inside a spec's `routeKinds` loop with that kind's `prefix`; `route` is the fixture key and defaults to `item`, `liveHost` is a selector of a server-rendered host of the item, and `leaveLink` is the name of the link that leaves for a page without the item. It registers the route's standard tests, which no spec restates: the page hydrates with 0 skipped components and no NG05xx message (development build); the head holds exactly one link of the item before leaving, none on the page it leaves for, and exactly one again after going back, with the item's sheet applied and `liveHost` computing `styled`; and, with JavaScript off, `liveHost` carries the item's class and presence attribute, the head holds the item's link, and axe finds nothing on `wcagTags`. T036 may add optional members whose defaults keep this call valid. `style-probe.ts` exports `expectStyledFrames(frames: readonly string[], options: { readonly styled: (value: string) => boolean; readonly label: string; readonly recordedAs?: string }): void`, which expects at least one sampled frame, pushes one annotation `{label}: {unstyled} of {sampled} frames unstyled` typed `recordedAs`, or `frames` without it, and expects no unstyled frame unless `recordedAs` names why the frames are recorded (`a4-frames` for upstream A4). It replaces `expectHydrationFrames` and every inline copy.
- Directive host (T038): the entry `@ngx-yeti/testing/test-bed` (`packages/ngx-yeti-testing/src/test-bed.ts`, mapped in tsconfig.base.json) exports `createDirectiveHost(type, options?: { readonly tagName?: string; readonly bindings?: Binding[] })`, which calls `TestBed.createDirective(type, options)`, awaits `whenStable()`, and resolves `{ fixture, element, destroy }`: `fixture` is what `createDirective` returned, `element` is its host narrowed to `HTMLElement`, and `destroy()` destroys the fixture and takes the host out of the document. A layer-2 spec's own `setup` function calls it and repeats none of that.
- Sanctioned selectors (T039): `packages/ngx-yeti/src/published-output.node.spec.ts` holds the table `sanctionedSelectors`, which maps a row id of `docs/specs/ledger.md` to every selector of that row's rule in `packages/ngx-yeti/accessibility.css`, one string per comma-separated selector. The spec fails when a selector of that stylesheet names a Yeti class and is outside `@layer ngx-yeti` or absent from the table, when a table entry matches no selector of the stylesheet, and when a key is not a row id of the ledger. A task that adds, changes, or removes such a rule changes its entry in the same commit.
