## Approach

- Item 4, both scripts: `readState` turns an unreadable or non-JSON state file into the same exit-2 refusal, with one JSON object under `--json`, that a state file of the wrong shape already gets; the state file (every write, including yeti-app's write that keeps survivors) goes through a temporary file in the same folder and a rename, so a reader sees the old file or the new one. Pitfall: a test that writes a malformed state file must not clobber the state of a session another run on this machine owns; use the per-checkout scratch folder the suites already use and restore it.
- Item 5, Storybook: `treeMembers` keeps only processes that started at or after the recorded root's `startTime`, on the live and the dead path; a member whose start time cannot be read is not dropped silently (report it, or keep it with its reason). A test can show it without real PID reuse: start a process that starts a long-lived child and exits, record the dead parent's PID with a `startTime` later than the child's start, and assert `down` does not name the child.
- Item 6, Storybook: the freshness check's newest source is taken from Git's list of tracked and untracked, not ignored, files under the build's source folders (`git ls-files -co --exclude-standard`, as `sourceFiles` in `tools/ci-local/run-job.mjs` does; skip listed files that no longer exist), and the failure detail names the newest file and its time. A file Git ignores, such as `.vitest-attachments` output, never makes `doctor` fail.
- Item 7, yeti-app: a listener query that timed out or failed ends the teardown wait at once (or the loop has one overall deadline), and `down` reports `listenerError`; SKILL.md states the bound. To test it without a real hung `pwsh`, the coder may add a test-only seam, as `CONTROL_SESSION_REGISTRY` already is (an environment variable read only by tests, named in SKILL.md as test-only).
- Cosmetics: Storybook `doctor` takes the launch time from `startedAt`, and a state file with no usable launch time gets its own detail, with the SKILL.md line that names `startTime` made true; the yeti-app `queryListeners` comment says what cosmetic-2 says; the Storybook live-path failure message, when the root is gone, names the PIDs to stop instead of "run down again" (kill-on-retry stays deferred with the lockout); Storybook's listener query keeps its error and the message shows it instead of "listeners []"; in both scripts a parsed `.session` entry without a string `socketPath` counts as possibly open with a reason; each suite has a test with `CONTROL_SESSION_REGISTRY` pointing at a file.
- Tests: every behaviour change above has a test in that script's `control.test.mjs` that fails without the change; the comment fix needs none. Keep every outcome and exit code the SKILL.md tables already state, the `left-open` union and `sessionLeftOpen`, the PID-and-start-time survivor match, and T047's and T055's refusal, flag, and daemon cycles. Each SKILL.md states every changed outcome, message, and bound.
- Keep both scripts typed (Interface contract); no JSDoc cast through `unknown`. Comments say only what the code cannot, with no planning id, date, or measurement.
- The suites build and launch on fixed ports (4000, 4200, 4310 to 4312, 4400, 4401); the orchestrator runs this task with no other heavy command, coder, or NVDA run. Never set `NX_DAEMON`.
