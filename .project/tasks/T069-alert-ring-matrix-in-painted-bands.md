## Approach

- Matrix first, in `box--paint` or in one new story of `packages/ngx-yeti/box/src/box.stories.ts` (a second story in the item's file is allowed by the stories skill; its id is `box--<story>` in kebab case, `meta.id` stays `box`). Axes: every alert variant and every emphasis read from Yeti's manifest at run time with `manifestValues('alert', 'data-variant')` and `manifestValues('alert', 'data-emphasis')` from `@ngx-yeti/testing` (never a hand-written list), plus the attribute left off for each axis (the default variant goes through `.alert:not([data-variant])`, alert.css:18, and the default emphasis is the absent attribute); bands that include at least `primary`, `white`, `black`, and one of `grey-0` to `grey-40` (the code reviewer's dark-scheme 2.17:1 band), more allowed; both schemes through the file's `schemeWrapper`. Each alert is Yeti's own markup (`class="alert"`, `data-variant`, `data-emphasis`) holding a labelled close button (`data-close`, `aria-label`), loaded through the existing `YetiStoryAlertStyles` host and waited on with `itemStyled('alert', ...)`, inside a band padded by `ringRoom` so a ring that leaves the alert would still lie on the band.
- What each case asserts: the control is focused by keyboard and matches `:focus-visible`, has a ring (`outlineStyle` not `none`), and the ring is at least 3:1 against the colour directly under it. Pitfall: that colour is not one element's `backgroundColor` when the alert's fill is translucent (`black` and `white` at the default emphasis) or transparent (`low`): composite the alert's fill over the band's with `composite` from `@ngx-yeti/testing`; `expectRingOn` as written does not composite. A high-emphasis case first asserts its alert is filled (fill alpha 1, not `rgba(0, 0, 0, 0)`), and a low-emphasis case keeps asserting its fill is transparent. Keep every existing assertion and band-order check of `box--paint`; the matrix replaces the two hand-picked alert cases only if it covers them (default variant, `primary` band, low and high).
- Exceptions: a combination no public Yeti token can bring to 3:1 is recorded as a new `docs/specs/upstream-bugs.md` row (next free id after Y18, Yeti, with the measured ratios and the alert.css and attributes.css lines) and listed in the story as one named constant of exceptions; the test asserts each listed combination is still under 3:1 (so a stale exception fails when Yeti fixes it) and every other combination is at least 3:1. No combination is skipped without that list. Expected from the tokens, not yet measured: none, since the high emphasis has a public `--yeti-on-<hue>`, `--yeti-white`, or `--yeti-black` per variant, and the translucent default emphasis can keep the band ink.
- Red first: run the matrix against the current rule (`.alert:not([data-emphasis='low'], [data-emphasis='high'])`) and record in the Log every failing combination with its ratio, per engine run, before changing the CSS. These measurements are the derivation: the new mapping is chosen from them, as T058 chose the band inks (tmp/afk-m002/tools/T058-design.md).
- The mapping, in `packages/ngx-yeti/ngx-yeti-globals.css`, constraints only: public Yeti tokens only, no `--_yeti-*` read (`privateReads: []`); stays in `@layer ngx-yeti`; the alert entries stay zero-specificity and before the 20 paint lines, so a surface that is itself a band keeps its band's ink and a band inside an alert sets its own; only `outline-color` changes through the existing ring rule; no `@scope`, no forced-colours change. Starting points from the reviewers (unverified until the matrix measures them): a high-emphasis alert's ink per variant copies the text colour Yeti gives that fill (`--_yeti-on-variant`, attributes.css:239-254 and alert.css:18) through its public token (`--yeti-on-<hue>`; `danger` reads the `alert` ladder; `--yeti-white` for `black`, `--yeti-black` for `white`; the absent variant is primary); the default emphasis of the translucent `black` and `white` variants keeps the band ink instead of Yeti's ring. The comment says what the code cannot (why the alert's ink depends on its variant and emphasis), with no measurement, date, or task id.
- Guard the copy, as T058 guarded the paint inks: `packages/ngx-yeti/src/accessibility.node.spec.ts` pins the new reset entries (`inkResets` result, the source check of each class and each attribute value an entry names against Yeti's source as written), and, if the mapping copies Yeti's per-variant `--_yeti-on-variant`, a check that reads those declarations from Yeti's source and fails when a pin move changes them or adds a variant the mapping lacks (reading Yeti's private token names in a spec is fine; the stylesheet itself reads none). The `'A11Y-35'` entry of `sanctionedSelectors` in `packages/ngx-yeti/src/published-output.node.spec.ts` matches the rule.
- Story time: the matrix is about ten variant values by four emphasis values by at least four bands by two schemes, so a tab per case is hundreds of focus moves in one play function. Do not raise a timeout (stories skill). Keep each story's run well under the test timeout in WebKit, with margin for load (T068 split `button--variants` by scheme after one long test flaked under the floor WebKit job's load): split the matrix into stories by scheme or by band if one story is slow, and record each story's duration per engine in the Log.
- Records, each made true for the new rule: ledger row A11Y-35 (package column selector text, Verified with the matrix result and any exception, Tested-by naming the story or stories); `docs/specs/upstream-bugs.md` Y18 (its sentence that inside a band a high-emphasis alert keeps the band's ring colour, corrected to what the rule now does) and any new exception row; the globals bullet of `packages/ngx-yeti/CHANGELOG.md` (line 37); the `box.md:207` Departures row of `.claude/skills/ngx-yeti-specs/SKILL.md`; line 48 of `.claude/skills/ngx-yeti-accessibility/SKILL.md` (the fill a ring reads on depends on the variant as well as the emphasis); step 5 of `.claude/skills/yeti-pin/SKILL.md` (the surface-selector count, and that a new variant or a changed `--_yeti-on-variant` needs the alert mapping re-derived). `docs/specs/` is otherwise immutable; only `ledger.md` and `upstream-bugs.md` change.
- Engines: the ring colour and compositing can differ by engine, so the Verify runs the box stories natively in Chromium and in Chromium, Firefox, and WebKit through the `ci unit` container job.
- Skills: `.claude/skills/ngx-yeti-accessibility/SKILL.md`, `.claude/skills/ngx-yeti-stories/SKILL.md`, `.claude/skills/ngx-yeti-specs/SKILL.md`, `.claude/skills/type-safety/SKILL.md`, `.claude/skills/yeti-pin/SKILL.md`.
