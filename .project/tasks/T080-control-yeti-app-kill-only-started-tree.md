Evidence, verbatim: "blocked. Measured: control-yeti-app's live `down` takes its member list from `tree()`, which matches children by parent PID alone, so a process that started before the recorded root but carries its PID as parent (PID reuse) is listed in `stopped`, survives taskkill /T (which itself filters it out), is written to `state.json` as a survivor, and the "run down again" retry kills it by PID and exits 0. That contradicts SKILL.md's own rule for the dead-root tree (:145-147, processes started before the recorded `start` are left out because Windows hands a dead PID out again) and Storybook's behaviour that Lars's 2026-10-15 ruling adopts. Inferred: on `up`'s launch-exited path `stopLaunch` reports `launchStopped: true` with the launch's surviving children unchecked and removes the state file, so SKILL.md:194's "stops the started tree ... nothing is left for `down`" does not hold, and the PID it kills may by then belong to another process. control-ngx-yeti-storybook passes: its live path uses `treeMembers`, and native taskkill /T spares pre-root processes (measured twice)."

P003's three risks: (1) live `down` lists, records and on retry kills a pre-root process that names the recorded root as its parent (PID reuse); (2) on `up`'s launch-exited path `stopLaunch` kills a PID that may belong to another process by then and reports `launchStopped: true` while the launch's children may still run; (3) `up`'s ready check and `doctor`'s port-owned check accept a pre-root process as the launch's own.

What T084 lands first (its Interface contract, below): control-yeti-app records, refreshes and stops its tree through the byte copy of the create skill's proctree.mjs, which counts a child only when it started no earlier than its parent, keeps a record after its parent exits, and stops only records whose PID still has their start time and command line (`reused` otherwise, never touched). That design covers risk (1) and the dead-PID half of risk (2), and T084's doctor `ports` line and ready check use the recorded tree (risk 3). It does not by itself record a child that the launch starts after `up`'s first snapshot and before the launch exits on the failed path, because the contract refreshes the tree only once ready; so the "launch exited, child still running" half of risk (2) may still hold on the T084 base. Whether each risk holds on the T084 base is measured by this task, not assumed.

T080 attempt 1 (Log below; its work saved at tmp/afk-m002/tools/T080-attempt1.patch, not landed) fixed P003 with local start-guarded walks, which proctree supersedes.
