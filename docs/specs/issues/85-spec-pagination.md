### Open

Each point is marked "(open: see ticket)" in the spec. Impact and confidence follow the trap-quadrant rule (map, Standing rulings, 2026-10-03). No point has HIGH impact, so none is in the trap quadrant. Point 1 still carries its options, because it decides what every pagination writes at the ends of its list.

1. **Previous on the first page and Next on the last** (spec Solution, usage rule 6, section 7 "Disabled Previous and Next", `pagination--first-page` and `pagination--last-page`, Out of Scope). Impact: MEDIUM (documented usage for every pagination; a directive could be added later without a break). Confidence: MEDIUM (the CSS is read; the focus loss is inferred, and layer 4 records it).
   - **Question.** Yeti's pagination docs do not say what Previous is on the first page; its docs example shows a Previous with `href="#"` beside a current page 1. The records give a disabled link one shape: a placeholder link with `role="link"` and `aria-disabled="true"`, marked by a directive ([ADR 0022](../adr/0022-button-declares-no-listeners.md) point 2; building-blocks 1.10 "Disabled"). The [button](../specs/button.md) spec puts it on `YetiButtonDisabledLink`, which matches only `a[yetiButton][disabled]`, and that split is itself open in [ticket 76](76-spec-button.md) point 2. What does a pagination write at its ends?
   - **Option A (recommended): leave Previous out on the first page and Next out on the last.** Approve: it is Yeti's markup with nothing in it that Yeti cannot draw; no dead link looks live; there is no new API; the compact form still shows the current link and the neighbour that remains. Cost: the row's length changes at the ends, and focus on Next falls to the `body` when Next leaves (B has the same cost).
   - **Option B: a placeholder link the consumer marks** (no target, `role="link"` and `aria-disabled="true"` written by hand). Dismiss: `pagination.css` has no `[aria-disabled]` rule, so the placeholder is drawn as a live target and still takes the hover tint (`pagination.css:31`), a dead control that looks live; ADR 0022 point 2 says the directive marks it, not the consumer; and a placeholder link is not focusable, so focus is lost as in A.
   - **Option C: `yetiButton` with `YetiButtonDisabledLink` on the pagination's Previous and Next.** Dismiss: `.button` adds its border and fill under `.pagination > ol > li > :is(a, span)`'s colour, size, and radius rules, a mixed look Yeti never shows (read, not measured), and it ties the pagination to the button's open point.
   - **Option D: a pagination-owned disabled-link directive, with package CSS for a muted look.** Dismiss: new API, and new package CSS outside the accessibility ruling (no WCAG AA criterion fails without a disabled look), for a state that option A avoids.
   - **Evidence and confidence.** `pagination.css` read at the pin (HIGH): no disabled rule, and `a:hover` matches any `a`. The specificity of C's mix: read, not measured (MEDIUM). Focus loss in A and B: inferred (MEDIUM); the e2e records the focused element after Next is clicked from page 8. Material's paginator keeps its buttons and disables them with `disabledInteractive` so that they keep focus (`NC/src/material/paginator/paginator.html:45-60`), but that is a button design, not links.
   - **To overrule.** For B, change usage rule 6 to the placeholder form, add `role` and `aria-disabled` to the `pagination--first-page` story's assertions, and accept the live look or record it as a ledger row. For D, add the directive to spec sections 2 and 4, a rule to the accessibility stylesheet with a ledger row, and layer-2 tests like the button spec's for `YetiButtonDisabledLink`. Decided 2026-10-03 in ticket 50, decision 176 (orchestrator, full AFK mode).
2. **The contrast threshold between the current link's fill and the background around it** (spec section 7, criteria 1.4.1 and 1.4.11; `pagination--variants`). Building-blocks 1.10 asks a spec whose item draws a state by colour against a neighbour ("a current page") to assert the ratio between the two states, but sets no threshold. Recommendation: at least 3:1 (WCAG 1.4.11's ratio for a visual state), in the light and dark schemes, for every variant the story renders; a variant that fails moves to an anti-pattern story with a ledger row owned by `pagination`, and no package CSS. This matches the button's open point 6 in [ticket 76](76-spec-button.md); decide both together. Impact: MEDIUM. Confidence: MEDIUM (`white`, `black`, and `warning` against the page in one scheme are the likely failures; not measured). Decided 2026-10-03 in ticket 50, decision 94 (orchestrator, full AFK mode).
3. **Which `aria-current` form the examples lead with** (usage rule 7). Recommendation: form (a), the consumer's binding from page state, with form (b) documented beside it, as [ticket 50](50-decide-open-points-of-the-specs.md) decision 87 chose for the breadcrumbs. Pagination adds a reason: pages are usually query parameters, where form (b) needs exact matching, one URL per page, and merged parameters (usage rules 4 and 9). Impact: LOW. Confidence: HIGH. Decided 2026-10-03 in ticket 50, decision 177 (orchestrator, full AFK mode).
4. **A pagination in a shrink-to-fit parent** (usage rule 11; one layer-4 measurement). The `nav` is an inline-size container (`pagination.css:5`), the same mechanism as the timeline's. Recommendation: usage rule 11 as written and the layer-4 case inside a `cluster`, as [ticket 50](50-decide-open-points-of-the-specs.md) decision 66 decided for the timeline. Impact: LOW. Confidence: HIGH. Decided 2026-10-03 in ticket 50, decision 178 (orchestrator, full AFK mode).
5. **`threshold="2xs"` matches no rule** (spec sections 1 and 2; `pagination--threshold`). The `width` vocabulary has `2xs`, ticket 26 row 132 types `threshold` as `YetiWidth`, and `pagination.css:41-63` has container rules for `xs` to `2xl` only, so a `2xs` pagination never compacts (read). `nav.css` and `card.css` have no `2xs` rule either (read). Recommendation: keep `YetiWidth` (a shared vocabulary type, building-blocks 1.4; ticket 26 grilling question 16); record the `2xs` result in the story without asserting it; add a Yeti row to [upstream-bugs.md](../upstream-bugs.md) naming `pagination`, `nav`, and `card` (verified *read*, no reproduction, not filed without the user's confirmation). Impact: LOW. Confidence: HIGH. Decided 2026-10-03 in ticket 50, decision 93 (orchestrator, full AFK mode).

## Answer

Resolved 2026-10-03 by Claude Opus 5.5. Spec: [specs/pagination.md](../specs/pagination.md).

One directive in `ngx-yeti/pagination`. The item directive `YetiPagination` on `nav[yetiPagination]` (`exportAs: 'yetiPagination'`) binds the static class `pagination` and the presence attribute `data-ngx-yeti-item-pagination` ([ADR 0045](../adr/0045-each-item-marks-its-host-with-its-own-attribute.md)). It binds `data-variant`, `data-size`, `data-threshold`, and `data-justify` from `variant: YetiVariant`, `size: YetiSizeControl` (`inert` on a `nav`), `threshold: YetiWidth`, and `justify: YetiJustify` (ticket 26 rows 130 to 133), and acquires the item file with `injectYetiItemStyles('pagination')`. It is types only, with no Aria and no listener. The name, `role="list"`, `rel`, the URLs, and `aria-current="page"` stay the consumer's, or `RouterLinkActive`'s with exact matching. Usage rule 8 forbids binding `aria-current` to `false`, because Yeti's CSS fills any `[aria-current]` like the current page. The spec owns ledger row A11Y-1f and adds its forced-colours rule (a system-colour border on `.pagination a[aria-current="page"]`) to the package's accessibility stylesheet; the row is confirmed unchanged.

Counts: 63 user stories, 15 usage rules, 11 story ids (plus an anti-pattern story for any variant that fails its contrast measurement), 5 open points (none with HIGH impact, so none in the trap quadrant). No open point blocks the spec: each has a recommendation the spec already carries. The spec adds no ledger row; open point 2 adds one only if a variant fails its measurement, and open point 5 adds one upstream-bugs row.
