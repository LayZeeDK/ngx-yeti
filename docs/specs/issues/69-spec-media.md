## Question

What is the Angular API of Yeti's `media` recipe, and what does its spec say? Its decisions are already made in the records: its row in `building-blocks.md` Part 2 (and the "Aria decisions" section where it applies), its rows in [Decide: how the package maps each of Yeti's `data-*` attributes](26-decide-yeti-data-attributes-mapping.md), its item file under [ADR 0060](../adr/0060-item-styles-are-counted-links-to-the-consumers-yeti-build.md), its ledger rows, and the shared specs it links to.

## Answer

Resolved 2026-10-03 by Claude Opus 5.5. Spec: [specs/media.md](../specs/media.md).

One directive in `ngx-yeti/media`, native platform, level 1, types only ([building-blocks.md](../building-blocks.md) Part 2 row 19): **`YetiMedia`**, the item directive, on `[yetiMedia]`. It binds the static `media` class and six inputs from ticket 26 rows 78 to 83: `width` (`YetiWidth`, kind `inert`), `ratio` (`YetiRatio`), `gap` (`YetiGap`), `align` (`YetiAlign`, kind `removed`, with `'[attr.align]': 'null'`), `max` (`YetiWidth`, kind `inert`), and `side` (`YetiSide`). It sets `data-ngx-yeti-item-media` ([ADR 0045](../adr/0045-each-item-marks-its-host-with-its-own-attribute.md)) and loads `recipes/media/media.css` as a counted link ([ADR 0060](../adr/0060-item-styles-are-counted-links-to-the-consumers-yeti-build.md)). There is no part directive and no injection token: Yeti finds the figure by element, and nothing would read a token. `YetiMedia` is not among the 46 names `yeti.d.ts` exports at the pin.

The spec links the three layouts the recipe is built from ([sidebar](../specs/sidebar.md), [frame](../specs/frame.md), [stack](../specs/stack.md)), and Test layers 1 and 4 compare the one-class form with the composed form, as Yeti's own test does. `side` is shared with [enter](../specs/enter.md): one value feeds both directives, neither writes a default, and a usage rule moves `yetiEnter` to a wrapper when the sides must differ. The spec owns ledger row A11Y-10d and meets it with 4.5:1 exact-formula assertions on the heading, the body text, and a `figcaption`, in light and dark schemes ([ticket 50](50-decide-open-points-of-the-specs.md) decision 8). It follows ticket 50's decisions on static `align` (9), `NgOptimizedImage` in a wrapper (35), `video` sources (36), and acquisition order (42).

Counts: 52 user stories, 13 usage rules, 6 story ids, 4 open points (none HIGH impact, so none is in the trap quadrant).

### Open

1. **Ledger A11Y-10d's "What Yeti does" cell** (spec section 7). Impact LOW, confidence HIGH (read). The cell reads "as A11Y-10b" (text over an image, the author's responsibility). That does not describe the `media`: its text sits beside the picture, never over it, and ticket 17's incomplete result names the example's heading as partially obscured in Chromium and Firefox. Recommendation: rewrite the cell as ticket 50 decisions 23 and 24 did for A11Y-10e and A11Y-10c: "Text beside a cropped picture on the page surface; axe left `color-contrast` incomplete on the example's heading as partially obscured, cause not traced." To overrule: leave the cell. The spec's assertions are the same either way. Decided 2026-10-03 in ticket 50, decision 79 (orchestrator, full AFK mode).
2. **`NgOptimizedImage` for the figure** (usage rule 6; Test layer 1). Impact MEDIUM, confidence MEDIUM (read in `ng_optimized_image.ts:260-263` and `:1103-1123` and in `media.css` and `reset.css`; not run). Decision 35 covers a frame, not a figure that is a direct child of a flex row. `fill` sets `position: absolute` on the image, which takes a direct-child figure out of the row. Recommendation: on a direct-child `img`, use `width` and `height` from the image file and never `fill`; Yeti's reset (`block-size: auto`) lets the crop's `aspect-ratio` win over the `height` attribute, and Angular's development-mode distortion warning appears when the file's ratio differs from `ratio`. On a wrapped figure, use decision 35's form: `fill` plus `position: relative` on the wrapper. Options dismissed: (b) `fill` everywhere, because it breaks the direct-child form; (c) a package style or wrapper for images, because building-blocks 1.13 rules out package CSS that is not for accessibility. To overrule: change usage rule 6 and the `media--figures` and `media--default` stories, which use `width` and `height`. If the stories show the warning is too noisy, write the stories with an image whose own ratio equals `ratio`. Decided 2026-10-03 in ticket 50, decision 80 (orchestrator, full AFK mode).
3. **`side` against WCAG 1.3.2 and 2.4.3** (usage rule 4; section 7). Impact MEDIUM, confidence MEDIUM. `side` draws the figure on the other side by `row-reverse` while the reading and focus order stay the source order, which Yeti's manifest states ("changes where the figure sits, not where it is read"). No record says whether that meets 1.3.2 and 2.4.3. Recommendation: it meets them when the author puts the figure where it is read, because with one figure and one body the figure's side does not change the text's meaning or how the controls are operated; state it as usage rule 4, add no ledger row (the package adds no feature) and no package code, and keep Test layer 1's assertions that tree order equals DOM order and that a focusable figure keeps its source place in the Tab sequence. Option dismissed: reordering the DOM to follow `side`, because it changes Yeti's markup and the server HTML. To overrule: add a ledger row for the gap and an anti-pattern story with a focusable figure reversed away from its reading order. Decided 2026-10-03 in ticket 50, decision 81 (orchestrator, full AFK mode).
4. **No `yetiFrame` or `yetiStack` on the media's own children** (usage rule 8). Impact LOW, confidence MEDIUM (specificity and custom-property inheritance read in `media.css`, `frame.css`, and `stack.css`; not measured). The body rule `.media > :not(...)` (specificity 0,1,1) outranks `.stack` (0,1,0), so a `yetiStack gap` on the body does nothing; a `yetiFrame` on the figure sets its own `--_yeti-aspect`, which the figure rule then reads, so the frame's ratio replaces the recipe's in a way Yeti does not document. Recommendation: keep the usage rule and point to the composed form, as Yeti's docs do; `yetiBox` on the body stays allowed. To overrule: remove the rule, and add a story that measures each pairing in three engines and documents what wins. Decided 2026-10-03 in ticket 50, decision 82 (orchestrator, full AFK mode).
