# 150. Spec: forgotten-import checks (shared utility)

Type: grilling
Status: resolved
Blocked by: 149

## Question

The user ruled on 2026-09-28 (Prototype: detecting a forgotten attribute directive import (old map, `issues/145-prototype-missing-directive-import-checks.md`), its user ruling, and ADR 0046): no import arrays, and four checks for a forgotten attribute directive import: in-family checks, a static check on documented APIs only, a runtime manifest check, and an opt-in `strictParents` flag. What exactly does the library ship for each, and what changes in the specs and shared documents?

### This ticket's probe

One question needed a measurement the sources could not give: does the template-outlet pattern the ADR names reach a parent that lives in another component's template? Experiment in `D:/tmp/nfs-wave-150/app/` (not committed; the peer prototype's `node_modules` linked with a junction, removed after the run): Angular 22.2.0, the peer prototype's ng-primitives stand-ins, whose accordion items and titles and whose menu items inject their parents without `optional`. A shell component renders `<ul nfsAccordion>` (and `<ul nfsDropdownMenu>`) in its own template and the consumer's `<ng-template>` inside it with `[ngTemplateOutlet]="items()" [ngTemplateOutletInjector]="accordionInjector()"`, where `accordionInjector = viewChild.required(NfsAccordion, {read: Injector})`; the consumer's page declares the items and imports only the item, title, and content directives. Prerendered in the development configuration: no NG0201; the HTML carried `.accordion-item`, `.accordion-title`, and `aria-expanded` on both items and the three menu items; the shells printed "registered items: 2" and "registered menu items: 3" in the same render (the view query is readable in the first update pass, no NG0100). Loaded in Chromium (Playwright 1.63, port 5540, stopped): "Angular hydrated 4 component(s) and 41 node(s), 0 component(s) were skipped", no warning, and a click on a title set `aria-expanded="true"`. Source reading agrees: `getOrCreateInjectable` looks in the embedded view's nodes, then the view's embedded injector, before the declaration view (`lookupTokenUsingEmbeddedInjector`), and a signal query returns results once the creation pass is over (`refreshSignalQuery`).

### Questions asked and answers

1. Where do the in-family helper and the runtime scan live? For the primary entry point: every entry point already imports it. Against: it imports nothing at runtime (Variant tooling D2) and the helper needs `@angular/core`; a new entry point would split the Runtime checks' code. Settled: `ngx-foundation-sites/media-query`, beside `nfsVariantCheck`, the precedent for a function exported for library directives; the Accordion now imports it, behind the inline guard, so production keeps nothing.
2. One call per directive, or separate calls for marking, the parent check, and the child probes? Settled: one, `nfsDirectiveCheck(directive, family?)`, called from the constructor inside `if (typeof ngDevMode === 'undefined' || ngDevMode)`. An unguarded call returning `null` like `nfsVariantCheck` would keep the names and peer lists in production; a hoisted guard kept 4336 B (PEER 4).
3. How does a part know its peers' attributes? Written into each call, or read from the manifest? Settled: class names in the call, attributes, selectors, entry points, and host classes from the Selector manifest, so no second list can drift from the selectors.
4. `afterRenderEffect` (Angular Aria's) or `afterEveryRender`? Settled: `afterEveryRender`; the effect missed a late orphan (PEER 2); about 1 ms per development render at 500 items.
5. The guard for server-rendered content not yet hydrated? Settled: `ng.getOwningComponent(el) === null` means unclaimed; the Structural class decides there (missing class is a forgotten import even in server HTML; present class counts as present, as the hybrid measured); a class-less directive stays undecided and is looked at again. One miss stated: a copied Foundation class on unclaimed HTML.
6. The runtime prototype read Angular's private compiled selector field; what replaces it? For a manifest lookup of `ng.getDirectives` instances by class name: development builds name classes `_Name`, and the two `NfsColumn` classes collide (RUNTIME 2). Settled: a development host record (`WeakMap<Element, Set<className>>`) that `nfsDirectiveCheck` fills, looked up through the manifest's attribute-to-directive entries, behind the class probe and the owner guard. `ng.getDirectives` is no longer needed; the only Angular debugging call is `getOwningComponent`, marked `@publicApi`. The registry approach's two false reports were both unclaimed server HTML, which the owner guard removes (RUNTIME 2); so the combination reuses measured parts, and the layer-2 and e2e matrices re-measure it.
7. Two checks see the same forgotten member; two reports? Settled: one report function for both, once per element and directive and once per realm per subject (directive, kind, owner), whichever check sees it first; the in-family text adds "Found by <Part>".
8. Does a library attribute on the wrong element (`<div nfsButton>`, `<a nfsAccordionTitle>`) count? For ignoring it: the static prototype listed `nfsButton` on a `div` as a consumer attribute. Against: the library owns the `nfs` prefix (ADR 0009), the runtime prototype reported it (expected 1), and without the distinction the in-family and runtime messages would ask for an import that changes nothing. Settled: all three checks report it as a wrong-element misuse (M3, NFS9003); the static test case's expectation changes from 0 to 1.
9. The rule each family spec follows? Settled: one line per part under Hierarchy and DI shape: its `nfsDirectiveCheck` name, its parent check (the providing and hosting directives, or "none" for a required injection), its child probes, its peers linked by reference or value (no probe), and what `strictParents` changes. The per-family lines are the family specs', not this spec's, so each family keeps one place for its DI; Audit: the specs against the architecture guide (old map, `issues/142-audit-specs-against-architecture-guide.md`), which already waits on this ticket, checks them.
10. `strictDirectiveImports`'s place among the Runtime checks? Settled: the fourth key of `NfsRuntimeChecks`, on in development with the per-check opt-out, never in production, because it reads Angular's development debugging global (a class-only production mode would ship the manifest in every bundle, RUNTIME 4).
11. How does it start when no library directive runs? For a generator that writes the provider into the application configuration: no install generator exists, and the Variant tooling spec keeps `ng add` out of scope; editing providers needs AST edits of several bootstrap shapes. Settled: `provideNfsRuntimeChecks()` with an optional argument adds an environment initializer that starts the scan; the install docs put it in every application configuration; a generator can add it in any release (ADR 0045).
12. The Selector manifest's generation "after the library build"? Against a pure post-build generation: the development module has to be inside `ngx-foundation-sites/media-query`, which is built before the entry points it describes. Settled: generated from the library's sources before the build (JSON and module), and asserted after the build against each entry point's compiled partial declarations, which is the post-build step that keeps it from drifting from what ships.
13. Does the manifest need more than the prototypes' fields? Found while reading the Menu, Nested menu, Magellan, and Responsive Menu specs: library directives host library directives (`NfsDropdownMenu` hosts `NfsMenu`, Magellan hosts `NfsSmoothScroll`), and consumers may write the hosted attribute beside the root, which the documented check would report as forgotten, because it can read host directives only from workspace source. Settled: a `hosts` field, from the library's own sources, applied like a workspace directive's host directives. Not measured by DOC, whose stand-ins had no library host directives; the node-level cases add both forms.
14. Manifest rules? Settled: every exported declarable with an attribute selector listed (element-only selectors are NG8001's); two classes of one name must share selector and host class (the host record keys by name); no selector names a secondary microsyntax key.
15. `strictParents`: its own provider, or a field of `NfsRuntimeChecks`? For its own provider: it is not a Runtime check (it throws, at construction, off by default). For the field: one configuration call, NgRx keeps flags with mixed defaults in one `runtimeChecks` object, and ADR 0046 calls it a flag. Settled: a field, off by default, development only, not accepted by the production provider, and documented as a flag beside the Runtime checks; the glossary's Runtime check entry is amended.
16. `strictParents` through `inject(token, {optional: !strict})` (NG0201) or the library's own error? Settled: the helper throws M8 at construction, which names the part, the parents, the import, and the outlet pattern; NG0201 names only the token, prints a class token as `_Name`, and misleads for projection (PEER 3). The effect is the same: the part fails as a required injection would.
17. Which families? For every optional injection: ADR 0046 says "parent injections that are optional by default". Against: several are optional because `null` is a supported form. Settled: every optional parent injection whose `null` only degrades with a development warning, eight families (Nested menu, Menu, Breadcrumbs, Pagination, Slider, Orbit, Equalizer, Drilldown back item); kept optional: Triggers' Nearest Openable, the Off-canvas panel's content, Abide's form and label tokens, `NfsSubmenu`'s `null` at the root level, `nfsTopBarRightToken`, `nfsRevealToken`, and the Drilldown root's wrapper, whose check runs only while drilldown is the live mode (a Responsive Menu whose rules do not name drilldown has none), which construction cannot know.
18. Token descriptions? Settled: every parent token, development only, "<token> (provided by <Directive> from '<entry point>' on an ancestor element declared in the same template)", as Angular's own tokens guard theirs; the only form no description reaches is a lookup by class.
19. The template-outlet pattern? Against the guide's `inject(Injector)` of the projecting component: it does not see providers on an element inside that component's own view. Settled: `viewChild.required(Parent, {read: Injector})` and `ngTemplateOutletInjector`, measured by this ticket's probe; it serves the required injections too.
20. The static check's builder, target, options? Settled from DOC: `ngx-foundation-sites:missing-imports` behind `nfs-imports`, options `buildTarget` (default `<project>:build`) and `tsConfig`, a `spec` configuration, no top-level await, `typescript` and `angular-html-parser` loaded on demand.
21. Which components does it check? Settled: every standalone component in the program's source files outside `node_modules`, so a workspace library's components are checked in each application that includes them, and Nx's `^default` input is right.
22. The notice for unresolvable `imports`? Settled: NFS9002, one line per component with the reason and the source text; every array skipped (the user's ruling), calls, spreads, non-classes, `standalone: false`, and template problems.
23. The zero-component guard? For failing whenever nothing was checked. Against: a workspace whose components all import arrays would fail for its style alone. Settled: NFS9004 fails when the program declares no component at all; all-skipped succeeds with its notices.
24. An ignore option? For: a consumer attribute equal to a library selector attribute has no escape. Against: the library owns the `nfs` prefix, and the one false report the ruling leaves (a packaged directive hosting a library directive with the library attribute written) is fixed by importing the library directive too, which Angular creates once. Settled: none; additive later.
25. An attribute index? Settled: from the start; the real manifest is about five times DOC's synthetic one, which already cost about 120 ms at 1047 components as a linear scan.
26. What the setup generator adds? Settled from DOC: the target, the `spec` configuration where `tsconfig.spec.json` exists, Nx `cache` and `inputs` on the target, `angular-html-parser` in `devDependencies`; no sync generator, no tsconfig, application configuration, or CI edit; it prints the CI step.
27. The oracle? Settled from DOC: the compiler-based check in the library's CI on every Angular minor over the prototypes' cases, the classes-only workspace, and the synthetic manifest; only the `ngNonBindable` difference is allowed.
28. Who guards the library's own stories? No static check sees a story's `render()` template. Settled: layer 1 runs in development mode, so the Storybook preview fails a story that logs a forgotten-import report (a storybook-conventions change, below); the Fixture app's `forgotten-imports` routes hold the runtime matrix, every other route is a negative control, and `nfs-imports` over the Fixture app must give exactly those routes' findings.
29. A new ADR? The decisions here refine ADR 0046 and ADR 0040 rather than reverse them. Settled: dated notes on both, no new record.
30. Glossary? Settled: new terms Forgotten import, Selector manifest, and In-family check (avoiding "peer check"), and an amended Runtime check.

### Decisions

1. Entry points export classes and no import arrays; the Accordion, Responsive Accordion Tabs, and Prototyping Utilities specs drop `NFS_ACCORDION`, `NFS_RESPONSIVE_ACCORDION_TABS`, and `nfsPrototypeClasses` (the user's ruling, ADR 0046).
2. Every library directive and component with an attribute selector calls `nfsDirectiveCheck(directive, family?)` from `ngx-foundation-sites/media-query` once, from its constructor, inside an inline `ngDevMode` guard; `ng-template` and `ng-container` hosts call nothing.
3. The Selector manifest (`directive`, `entryPoint`, `selector`, `hostClass`, `hosts`) is generated from the library's sources before the build, as JSON for the static check and a development-only module for the runtime checks, and asserted against the compiled partial declarations after the build; its generator enforces three rules (every attribute-selector declarable listed, one selector per class name, no secondary microsyntax key).
4. The verdict shared by both development checks: wrong element, then the Structural class, then Angular's owner for unclaimed HTML, then the development host record; no private Angular field is read.
5. One report function: once per element and directive, once per realm per subject; `console.warn(message, element)`; messages M1 to M8.
6. In-family checks: the parent check (out of reach, forgotten parent, stands alone) and the child probe (nearest-ancestor scope), in `afterEveryRender`, no report for a part with no child, no switch.
7. The rule for family specs: one line per part (name, parent check, child probes, peers by reference or value, `strictParents` effect).
8. `strictDirectiveImports`: the fourth Runtime check, on in development with an opt-out, never in production; one `afterEveryRender` scan per application over `MutationObserver`-added subtrees with `takeRecords()`; started by the first `nfsDirectiveCheck` or by `provideNfsRuntimeChecks()`, whose argument becomes optional; the install docs name that line.
9. `strictParents`: a field of `NfsRuntimeChecks`, off by default, development only; `nfsDirectiveCheck` throws M8 at construction for the fifteen parts of eight families in the spec's table; the other optional injections stay optional, each with its reason.
10. Every parent token has a development-only description naming its provider, entry point, and the same-template rule.
11. The template-outlet pattern (`viewChild.required(Parent, {read: Injector})` with `ngTemplateOutletInjector`) is the documented form for parts projected across templates, measured by this ticket's probe.
12. The static check: `ngx-foundation-sites:missing-imports` behind `nfs-imports` (`buildTarget`, `tsConfig`, a `spec` configuration); every standalone component outside `node_modules`; library `hosts` applied; an attribute index; NFS9001 (forgotten import) and NFS9003 (wrong element) fail, NFS9002 skips with a reason, NFS9004 fails when the program declares no component; no ignore option.
13. The setup generator of the same name adds the target, the Nx cache inputs, and `angular-html-parser`, and nothing else.
14. The library's CI keeps the compiler-based check as the oracle on every Angular minor.
15. Tests: layer 1 fails a story that logs a forgotten-import report; layer 2 runs the prototypes' matrices over the library's own directives; layer 3 covers the SSR smoke, the manifest generator, the static check's cases, the builder, the generator, and scratch workspaces; layer 4 runs the runtime matrix on the Fixture app's `forgotten-imports` routes in three engines, uses every other route as a negative control, checks `nfs-imports` over the Fixture app, and asserts the production bundle carries nothing.
