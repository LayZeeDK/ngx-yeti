# Control the ngx-yeti Storybook

Launches the `ngx-yeti` Storybook (`packages/ngx-yeti/.storybook/`, `@storybook/angular-vite` 10.6) through its Nx targets, checks it is worth driving, opens stories in their `iframe.html` with playwright-cli, runs play functions, and captures the a11y addon's axe report. Skip it for a whole-suite check: `npm exec -- nx test-storybook ngx-yeti` runs every story's play function and axe gate without a server.

## Pick a flow

| Flow             | Flag    | Nx target                   |
| ---------------- | ------- | --------------------------- |
| static (default) | none    | `ngx-yeti:static-storybook` |
| dev              | `--dev` | `ngx-yeti:storybook`        |

The static flow serves the built Storybook that layer 4 (`apps/ngx-yeti-e2e`) opens; use it for proofs. The dev flow (`storybook dev`) reloads on edits; use it while writing a story. Sessions use playwright-cli's in-memory profile; nothing to remove. Each flow opens one port:

| Port   | Kind    | Default | How it moves                                                                                                                                     |
| ------ | ------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| static | derived | 4401    | `--port=<port>`, passed through to the `static-storybook` target's `http-server` (measured: listened on 4450 with `up --port=4450`, 2026-10-17)  |
| dev    | derived | 4400    | `--port=<port>`, passed through to the `storybook` target's `storybook dev` (measured: listened on 4452 with `up --dev --port=4452`, 2026-10-17) |

The script finds the checkout kind itself: `.git` is a directory in the main checkout and a file in a linked worktree. It numbers slots: the main checkout takes slot 0, the ports above; a worktree takes slot 1 to 99 from a SHA-1 of its path, so its usual port stays the same from run to run, and slot `s` gives static `4421 + 2 * (s - 1)` and dev `4420 + 2 * (s - 1)`, within 4420-4617, below control-yeti-app's 4620-4818, so the two skills never derive the same port. `up` checks the flow's port before launching; when it is busy, or another process takes it before the server binds, `up` moves to the next slot (wrapping within 1 to 99 from a worktree, never onto slot 0), at most 10 slots, and `info.ports[].reason` says `fell back from <port>: held by PID <pid>`, naming the process that held it before the launch or took it after the check. Ten busy slots exit 2 naming each port and its holder. `up --port=<n>` sets the port with no fallback: a busy `n` exits 2 naming its holder, and from a worktree 4400 and 4401 are refused.

## Launch

```bash
node .claude/skills/control-ngx-yeti-storybook/scripts/control.mjs up --json
node .claude/skills/control-ngx-yeti-storybook/scripts/control.mjs up --dev --json
```

Run from the repository root. Underneath it spawns `node node_modules/nx/dist/bin/nx.js run ngx-yeti:static-storybook --port=<port>` (or `ngx-yeti:storybook --port=<port>`) detached, with `NX_TUI=false` and `NX_NO_CLOUD=true`, and logs to `<evidenceDir>/server.log`. The Nx daemon stays running: the script sets nothing about it and never stops it, since other Nx work in the checkout needs it; only removing a worktree the work created stops that worktree's daemon (`nx daemon --stop`, run from it). A state file of this flow whose root no longer runs (or whose root PID now belongs to another process) is not left to rot: `up` first stops every record of its tree that still matches, as `down` would, reports what it stopped as `staleStopped`, and only then removes the file; a record that survives or a root refused as `reused` keeps the file and exits 2 as `down` does. A live recorded root refuses with `already up`. Right after the spawn `up` records the process tree through `scripts/proctree.mjs` (the spawned PID with its start time and command line, and every descendant), refreshes it while it waits and once ready, and keeps it in the state file as `tree`, root first. Every listener on the port must be a live process of that tree: a foreign listener beside the server (on another address of the same port) counts as the port taken. `static-storybook` first runs `build-storybook` (cached by Nx) and `yeti-css:yeti-build`, then serves `packages/ngx-yeti/storybook-static` with `http-server`.

Ready means: `<url>/index.json` lists `card--stretched-link`, and that story, opened with `embed=true` in the repo's Playwright Chromium, reaches render phase `finished` without Storybook's error display. Measured on this machine (Windows 11 ARM64): static 8.5-16.5 s with `build-storybook` from the Nx cache, about 26 s with a fresh build; dev 8.9-17.6 s. `up` gives up after 600 s.

## Doctor

```bash
node .claude/skills/control-ngx-yeti-storybook/scripts/control.mjs doctor --json
node .claude/skills/control-ngx-yeti-storybook/scripts/control.mjs doctor --url=http://localhost:4401 --json
```

Read-only, apart from refreshing the recorded `tree` in the state file (a new descendant is added; a record is never dropped). Each check is one entry in `checks` with `pass`, `fail` or `skipped` (`map-fresh`: `pass` or `warn`):

- `process alive`: the recorded root runs with its recorded start time and command line.
- `ports`: every port of `ports` listens, and every listener on it is a live process of the recorded tree. `[OK] ports: static 4401 (derived)`, with the fallback reason after the kind when there is one; `[ERROR] ports: static 4401 not listening` or `static 4401 held by PID 9120, not the recorded tree`; a listener query that fails or gives no answer in 30 s fails the line with its error; `[SKIP] ports: --url given; ownership not checked`.
- `index lists known story`: `index.json` has `card--stretched-link`.
- `known story renders`: phase `finished`, no `sb-show-errordisplay`, `#storybook-root` has content.
- `no console errors`: no console error or page error on first load (the `favicon.ico` 404 of `http-server` is ignored).
- `build matches checkout`: static, the server log shows `nx run ngx-yeti:build-storybook` (built or restored from the Nx cache at launch) and no file Git lists under `packages/ngx-yeti`, `packages/ngx-yeti-testing` (the shared story helpers) or `vendor/yeti` changed after the recorded `startedAt`. The sources are Git's tracked and untracked files (`git ls-files -co --exclude-standard`, listed files that no longer exist skipped), so ignored output such as `.vitest-attachments`, `__screenshots__`, `storybook-static` or `dist` never fails the check. The detail names the newest file and its time, on a pass and on a fail. A state file whose `startedAt` is not a time fails with `the state file records no usable launch time`. An Nx cache restore keeps the original build's file times, so the sources are compared with the launch, not with `storybook-static`; dev, the server log has no `ERROR` or `Error:` line.
- `map-fresh`: never fails. `pass` (`[OK] map-fresh: 3 features fresh`) when every feature of `features/` is fresh in `features/.proven.json`, `warn` (`[WARN]`) naming the stale ones (since which commit, how many files changed) and the unproven ones. It comes from `mapFresh` in `scripts/fingerprint.mjs`, which reads this skill's folder from the script's own location, never the working directory.

With `--url`, `process alive`, `ports` and `build matches checkout` report `skipped`; the page checks and `map-fresh` still run. Exit 0 healthy, 1 not healthy (the failing check is named; `map-fresh` is never one, so it never changes the exit code), 2 could not run (no state file and no `--url`, or an exception such as a missing Chromium or a story that never settles: `could not run: <error>`).

## Drive

Driver: playwright-cli, session `control-ngx-yeti-storybook-<checkout id>-<flow>`, where the checkout id is `main` or `wt-<8 hex of the checkout path>` (the `session` field of `up` and `info`). playwright-cli's session registry is machine-wide, so the name is per checkout and flow, never per port: another checkout that takes this one's port never shares its session. Run playwright-cli from the repository root: a `close` issued from another working directory answered "is not open" for a session that was open (measured). Open stories in `iframe.html`, never the manager UI, whose own controls sit outside the story. Story and gate rules live in the `ngx-yeti-stories` skill.

- **Open a story without rerunning its play function:** `iframe.html?id=<story-id>&viewMode=story&embed=true`. `embed=true` turns Storybook's autoplay off, as `openStory` in `apps/ngx-yeti-e2e/src/open-story.ts` relies on; `window.__STORYBOOK_PREVIEW__.currentRender.renderOptions.autoplay` reads `false`.
- **Run its play function:** open the same URL without `embed=true`: `iframe.html?id=<story-id>&viewMode=story`. Autoplay is on and the play function runs once after render. To run it again and capture its result, emit `forceRemount` and wait for `storyFinished` (recipe in `features/play-functions.md`).
- **Run it as the repo's test:** `npm exec -- nx run ngx-yeti:test-storybook --skipNxCache -- card/src/card.stories.ts -t "Stretched Link"` runs that one story's render, play function, console gate and axe gate in Vitest browser mode, with no server needed (measured: 1 passed, the rest of the file skipped).

```bash
playwright-cli -s=control-ngx-yeti-storybook-wt-1a2b3c4d-static open "http://localhost:4483/iframe.html?id=card--stretched-link&viewMode=story"
playwright-cli -s=control-ngx-yeti-storybook-wt-1a2b3c4d-static snapshot
```

Selectors, in order: roles and accessible names (`getByRole('button', { name: 'Save' })`), labels (`getByLabel`), the attributes and classes Yeti directives bind (`[data-ratio]`, and `.card`, Yeti's own class that `yetiCard` puts on its host), snapshot refs. The interaction loop: snapshot, one action, fresh snapshot, check the expected change. Wait by polling an end state, never a fixed sleep: run the wait recipe in `features/README.md` after every `open` or `goto`; it returns once `currentRender.phase` is `finished`, `errored` or `aborted` (the phases `open-story.ts` waits for). Recipes per feature: `features/README.md`.

## Inspect

- `playwright-cli -s=<session> console error` and `requests` read the console and network.
- `playwright-cli -s=<session> --raw eval "() => window.__STORYBOOK_PREVIEW__.currentRender.phase"` reads the render phase; `renderOptions.autoplay` says whether the play function ran.
- The `storyFinished` event on `window.__STORYBOOK_ADDONS_CHANNEL__` carries the story's status (`success` or `error`: a play function that threw, a failed `console.error` gate, or a failed axe report) and the a11y addon's full axe report (`features/axe-results.md`).
- Not reachable: Angular DevTools (a browser extension for humans, manual only). Not covered: the Storybook MCP addon, which this repo does not install; `window.ng` was not probed.

## Evidence

Evidence lives in `tmp/control-ngx-yeti-storybook/<flow>-<timestamp>/` (the `evidenceDir` of `up` and `info`; `tmp` is git-ignored). `down` keeps it. A story proof captures:

- the story URL (it reproduces the state, args included);
- a snapshot before the action: `playwright-cli -s=<session> snapshot --filename=<evidenceDir>/<story-id>.before.yml`;
- a snapshot after the action: `playwright-cli -s=<session> snapshot --filename=<evidenceDir>/<story-id>.after-play.yml`;
- the `storyFinished` result with the axe report: `<evidenceDir>/<story-id>.story-finished.json`;
- a screenshot: `playwright-cli -s=<session> screenshot --filename=<evidenceDir>/<story-id>.png`;
- `server.log`, written by `up`.

Proof rules: `features/README.md`. playwright-cli also writes `.playwright-cli/` in the working directory; it is ignored and never evidence.

## Cleanup

```bash
node .claude/skills/control-ngx-yeti-storybook/scripts/control.mjs down --json
node .claude/skills/control-ngx-yeti-storybook/scripts/control.mjs down --dev --json
```

Closes the run's playwright-cli session by name, takes a last snapshot of the tree below the recorded root while it still runs, and stops every recorded process through `stop` of `scripts/proctree.mjs`: by PID, children first, each only while its PID still has its recorded start time and command line, so a child whose parent already exited (an orphaned grandchild) is stopped too. It then waits up to 15 s for the port to stop answering, removes the state file, and keeps the evidence directory. It leaves the Nx daemon running. It runs playwright-cli's own script (`@playwright/cli/playwright-cli.js` beside the shim) under this Node with the session as an argument, so the name never reaches a shell. `sessionClose.outcome` is one of:

| Outcome     | Means                                                                                                                                                                                                                                       | `down` exit |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `closed`    | playwright-cli closed the session                                                                                                                                                                                                           | 0           |
| `not-open`  | playwright-cli answered that the session was not open                                                                                                                                                                                       | 0           |
| `absent`    | no playwright-cli on `PATH`, and the session registry lists no open session of that name                                                                                                                                                    | 0           |
| `left-open` | no playwright-cli on `PATH`, and the registry lists the session as open, holds a `<session>.session` entry that could not be read or parsed or that has no string `socketPath`, or its folder could not be listed (`detail` names the path) | 1           |
| `timeout`   | playwright-cli gave no answer in 30 s                                                                                                                                                                                                       | 1           |
| `failed`    | playwright-cli exited non-zero (`detail` holds its output)                                                                                                                                                                                  | 1           |

No playwright-cli on `PATH` means the lookup found no `@playwright/cli/playwright-cli.js` beside a `PATH` directory (npm's global layout; a Volta, pnpm or scoop install, or `npx`, misses it), so `down` closed nothing; it then reads playwright-cli's session registry (`ms-playwright/daemon/*/<session>.session` in the user cache directory, `%LOCALAPPDATA%` on Windows, whose socket answers while the session is open). An entry that cannot be read or parsed, or that has no string `socketPath` (a format the script does not know), counts as possibly open; `down` still stops the tree and prints its result. A `left-open`, `timeout` or `failed` close makes `down` exit 1 with `teardown incomplete` naming the session and the command that closes it.

Refusals and exits, from "Process trees" of the create skill's `references/generated-skill.md`:

- A live process on the recorded root PID whose start time or command line differs from the state file: the root is refused as `reused` and left running, the session is still closed and every other record that still matches is still stopped; exit 2, `start-time or command-line mismatch: left it running and stopped the other recorded processes that still match`, state kept.
- A recorded root that is no longer running is not a refusal: `down` closes the session, stops the recorded descendants that still match, and exits 0 with `pid <root> was not running; removed the state file`.
- A record still running after `stop`'s last round (`refused` with reason `survived`): exit 2 naming it, the state file kept with the refreshed `tree`; run `down` again.
- A descendant refused as `reused` (its PID now belongs to another process) or `helper` (a shared helper such as the Nx daemon, which the tree never holds): listed in `notes` and `refused`, never stopped, and the exit code stays as it is.
- When the port still answers after 15 s, the process holding it is outside the recorded tree: `down` removes the state file (every recorded process is stopped or gone, so another `down` could do no more) and exits 1 with `teardown incomplete: port <port> still held by <PID and escaped command line>, not the recorded tree; it may be another session's instance or the user's own, so down left it running; removed <state file>`, or the listener query's error when it failed or gave no answer in 30 s. It never offers a process outside the tree for stopping.

Never use `playwright-cli close-all` or `kill-all`: they reach every session on the machine.

## Helpers

`scripts/control.mjs <command> [--dev] [--port=<n>] [--url=<origin>] [--json]`

| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `up`     | Picks the slot and port ("Pick a flow"), launches the flow's target, records the process tree, polls readiness, writes the state file                                           | 0 ready; 1 the root never appeared in the process table (its tree is stopped), the server exited before ready (its recorded tree is stopped and the state file removed), did not render, a PID outside the tree listened on the port with `--port`, or was not ready (these three keep the state file: run `down`), or a stop of the launch left a recorded process running after `stop`'s last round (state kept: run `down`); 2 already up, a stale state file whose tree could not all be stopped, `--port` busy or refused, ten busy slots, a listener query that failed after the launch (the message names the server PID and `run down`), or could not run |

| `down`   | Closes the session, stops the recorded tree through `proctree.mjs`, waits for the port, removes the state file (the session close and the stop run on a dead recorded root too) | 0 stopped, or the root already gone with the port free; 1 teardown incomplete (the port still answers, or a `left-open`, `timeout` or `failed` session close); 2 no state file, refused mismatch, a record that survived, or could not run                                                                                                                                                                                                                                                                                                                                                                                                                        |

Output, besides `command`, `flow`, `exitCode` and `message`:

- `up`: `staleStopped` (`stoppedPids`, `gonePids`, `refused`) when it stopped a stale state file's tree; on exit 0 the whole state (below) plus `readyMs`; on a story that did not render, `render` (`phase`, `errorDisplay`, `rootChildren`, `consoleErrors`) and the state; on a server that exited, `stoppedPids`, `gonePids`, `refused`, `tree`, `log` and `logTail` (the last 20 log lines); on a root that never appeared, `launchStopped`, `stoppedPids`, `gonePids`, `refused` and `log`; on a timeout, the state and `logTail`; on a busy `--port`, `owner` (the listener PIDs).
- `doctor`: `url` and `checks` (`name`, `status` (`pass`, `fail`, `skipped`, or `warn` for `map-fresh`), `detail`).
- `info`: on exit 0 `worktree`, `statePath` and the state; on a missing state file `port`, `session` and `worktree` for the flow's own slot.
- `down`: `stoppedPids`, `gonePids` (recorded, already exited), `refused` (`pid`, `reason`, `process`: the escaped line `describe` gives), `notes`, `recordedPidRunning`, `portFree`, `port`, `session`, `sessionClose` and `evidenceDir`; on the exit-2 survived or reused path `stoppedPids`, `gonePids`, `refused`, `notes`, `sessionClose` and `statePath`.
- A refused state file, and an exception (`could not run`), give `statePath`.

`--dev` picks the dev flow; without it the static flow. `--port=<n>` belongs to `up` only, and `--url=<origin>` to `doctor` only: on another command each exits 2 with `unknown argument <arg>`, so a caller never reads a result about the recorded instance as one about the named URL. Any other argument, a flag written with a space instead of `=` (`--url http://...`, `--port 4401`) and a second command exit 2 with `unknown argument <arg>` before anything runs. A command other than the four, a name every object has such as `toString` included, exits 2 with the usage line. Every command refuses (exit 2, nothing run) a state file that cannot be read or is not JSON (a truncated write, for example: `could not be read as JSON`), that is not an object, whose `session` is not `[\w-]` only, whose `pid` is not a positive integer, whose `tree` is not a list of process records (`pid`, `ppid`, `start`, `commandLine`) rooted at that `pid`, whose `port` is not 1 to 65535 or whose `ports` is not a list of port entries, or whose `url`, `target` or `log` is not a string. A state file written by a control.mjs before process trees (a `pid` and `port` but no `tree`) exits 2 with `was written by a control.mjs without a process tree (pid <p>, port <n>); check that pid <p> is this checkout's server, stop it by hand, then delete <file>`: no tree is ever guessed. An exception inside a command (a missing Chromium, a story that never settles, a process listing that fails) exits 2 with one JSON object whose `message` starts `could not run:`; from `up`, after the launch, the message adds the server PID that may still run and ends `run down` (or `stop it yourself` when the state file was never written). `up --port` and `doctor` refuse the main checkout's ports from a worktree; the derived range never holds them. `--json` prints one JSON object (`command`, `flow`, `exitCode`, `message` and the command's fields); without it, `[OK]`/`[ERROR]`/`[SKIP]`/`[WARN]` lines, with every control, format and bidi character escaped as `\uXXXX` (`printable` of `scripts/fingerprint.mjs`), since a recorded command line is never printed raw. State: `tmp/control-ngx-yeti-storybook/state-<flow>.json`, written to a temporary file in the same folder and renamed over it, so a reader sees the old file or the new one; it holds `pid`, `port`, `slot`, `ports` (`[{ name, port, kind, reason? }]`, one entry for the flow's row), `url`, `flow`, `target`, `session` (`control-ngx-yeti-storybook-<checkout id>-<flow>`), `commandLine`, `startedAt`, `evidenceDir`, `log` and `tree` (`[{ pid, ppid, start, commandLine }]`, root first, `start` in milliseconds since the epoch). `info --json` prints all of it.

`scripts/proctree.mjs` is a byte copy of `~/.claude/skills/lars-create-verification/scripts/proctree.mjs` (Prettier skips it through `.prettierignore`); copy it again after that one changes, never edit it here. `control.mjs` imports `snapshot`, `merge`, `stop`, `describe`, `matches` and `processTable` from it. It reads the process table through one `Win32_Process` query run by `%ProgramFiles%\PowerShell\7\pwsh.exe` (or Windows PowerShell) by absolute path, stops by PID only, and never records or stops the Nx daemon.

It builds the static Storybook, so nothing else may build in the checkout while it runs. It launches no dev flow and never stops the Nx daemon. Every test passes in the main checkout and in a linked worktree (the tests derive slots, ports and the session's checkout id from the checkout they run in), and every test that can start an instance stops it in its `t.after`, also when an assertion fails.

`node .claude/skills/control-ngx-yeti-storybook/scripts/fingerprint.mjs <command> [flags]` is the proof manifest's script, a byte copy of `~/.claude/skills/lars-create-verification/scripts/fingerprint.mjs`: copy it again after that one changes, never edit it here (Prettier skips it, and `features/.proven.json`, through `.prettierignore`). It spawns nothing and writes only the manifest.

| Command                                       | Does                                                                                                                                                                                                                                                                                                                                                                                                          | Exit codes                                                         |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `record --feature <id> [--entries <path>...]` | records the files feature `<id>` (`features/<id>.md`) depends on and their git blob hashes in `features/.proven.json`: the import closure of the entries through the repository's TypeScript and the nearest `tsconfig.json`, plus Angular `templateUrl` and `styleUrl(s)`; entries are repository-relative, and without `--entries` the recorded ones are reused; writes nothing when files and hashes match | 0 written or unchanged, 2 refused                                  |
| `check [--feature <id>]`                      | compares each recorded hash with the file now: `fresh`, `stale` (a file changed, went missing or became a link) or `unproven` (no entry)                                                                                                                                                                                                                                                                      | 0 every feature fresh, 1 one is stale or unproven, 2 could not run |

Both take `--json`. Record a feature only after a live pass proved every sub-feature of it (`/lars-maintain-verification`); `/lars-verify` runs `check --feature <id>` before a claim.

## Gotchas

- Proof run, first try: importing Playwright by a `C:\` path failed with `ERR_UNSUPPORTED_ESM_URL_SCHEME`; the script imports it through a `file://` URL.
- Nx's bin is `node_modules/nx/dist/bin/nx.js`, not `node_modules/nx/bin/nx.js` (Nx 23.2.1).
- `playwright-cli close` exits 0 whether or not the session was open; `down` reads its output (`sessionClose.outcome`: `closed` or `not-open`).
- In this repository the GSD Path guard hook rejects a shell write target it cannot resolve (`> $E/file.json`): write the literal evidence path from `info`.
- PowerShell and cmd.exe cut a URL at `&`: in PowerShell use `playwright-cli --% -s=<session> open "<url>"`; in cmd.exe write `^&`. Git Bash needs only the quotes.
- `http-server` has no favicon, so every page logs one `favicon.ico` 404 console error; it is not a story error.
- A green local run proves Chromium only; `test-storybook` runs three engines only when `CI` is set (`ngx-yeti-stories`).
- In a worktree whose `node_modules` is a junction to the main checkout, `test-storybook` can fail to import modules (`Failed to fetch dynamically imported module` for the main checkout's `node_modules/@angular/compiler`); `up`, `doctor` and driving work. Run `npm ci` in the worktree before the test.
- In the main checkout the static flow holds 4401, which layer 4 (`apps/ngx-yeti-e2e`) and the screen-reader runs (`apps/screen-reader-e2e`) start their own server on with `reuseExistingServer: false`: `down` before running them, drive from a worktree, whose derived port leaves 4401 free, or pass `up --port=<n>`.
- The static flow's `http-server` (through Nx's file-server) takes the next free port when any address of its port is busy as it starts: with 127.0.0.1:4467 held after `up`'s check, it served 4468 while `up` watched 4467 (measured 2026-10-17). `up` then sees no story on its port until another process answers there or the 600 s run out; `down` still stops the server, since it is in the recorded tree.
- The Nx daemon stays running after `down`. An earlier version stopped it on every `down`; Lars ruled that only removing a worktree the work created stops it ("In an Nx workspace, it is needed continuously.").
- `userEvent.hover` in a play function does not set `:hover`; hover and media emulation belong to layers 2 and 4, not to a play-function recipe.
